## Namespace / model-emission decision

Bare top-level emission is rejected (severe collisions: `Image`/`Video`/`Audio`/`Color`/`Element`/`Data`
clash with SwiftUI/Foundation/consumer types; per-operation selection variance).

- **Axis A — identity:** fragments are the shared-model unit (`CookFields`→`Cook`, reused across ops).
  Inline (non-fragment) selections get operation-scoped nested glue types.
- **Axis B — namespacing:** configurable caseless-enum namespace (default `CachebayModels`/schema-name,
  consumer-overridable like Apollo's `schemaNamespace`); optional module mode for full isolation.
  Switch arms stay unqualified (`case .video(let v)`), so ergonomics survive.
- **Macro coupling:** `@attached(extension)` macros attach only to file-scope types. So the macros are
  **`@attached(member)`-only**; conformances (`Sendable/Hashable/Equatable/Codable`) are declared on the
  type (CLI-emitted in production, hand-written in the spike) and compiler-synthesized from stored `let`s.
  This makes namespacing/nesting always compile. The spike's `Element.Video` nesting is the wk1 canary.

## Decode strategy (read path) — no extra pass

A normalized cache intrinsically has two phases: **normalize** (write: response → entity records) and
**materialize** (read: records → typed value). This is NOT a redundant double-decode — the consumer struct
is *reassembled* from deduplicated, ref-linked records (often with zero network, possibly merged across
operations/mutations/optimistic layers), so `JSONDecoder().decode(T.self, from: blob)` does not apply
(there is no single blob; there is a graph). We do **not** use Codable on the hot path — `init?(_dataDict:)`
reads the already-parsed `JSONValue` enum directly (faster than Codable's keyed-container overhead).

v1.0 adds **no read pass** vs today: materialize already walks the plan (refs + version snapshots +
fingerprints); v1.0 changes what that walk *produces* (typed structs vs a `JSONValue` dict tree). Reads then
cost ~1 ns. Two implementation options, decided by the **wk6 perf gate**:
- **Layered** (start here): materialize builds the small per-result tree, then `Op.Data(_dataDict:)` decodes
  it — 1 assemble + 1 cheap decode over *selected fields only* (not the cache); decoupled, TDD-friendly.
- **Fused** (§5 ideal): construct structs inside the materialize walk — 1 walk, but couples materialize to
  generated decoders. Adopt if the decode walk shows in profiles at wk6.

### Macro emission contracts

`@CachebayData(typename:)` — `@attached(member)`:
- public memberwise init: `__typename` defaults to the typename literal; `@CachebayDefault(x)` → `= x`;
  optional → `= nil`; else required.
- `@_spi(Cachebay) init?(_dataDict: [String: Cachebay.JSONValue])`: typename-guarded eager decode;
  builtins via `.string/.int/.double/.bool`; custom scalars via `CachebayScalar` (WS9); nested via own `init?`;
  lists via `compactMap`. Required missing/unparseable → `nil` (D3 lean). Optional → nil-fill. Extra keys ignored.
- `@_spi(Cachebay) func __dataDict() -> [String: Cachebay.JSONValue]` round-trip bridge.

`@CachebayDefault(_:)` — no-op `@attached(peer, names:[])` marker; read by `@CachebayData`.

`@CachebayInterface` / `@CachebayUnion` — `@attached(member)`:
- lifted shared accessors switching all cases incl `.unknown(let s)` (§3.1, no optional/force-unwrap).
- `init?`: try each variant's self-guarding `init?`, else `.unknown(Shared(_dataDict:)!)`.
- Union = same minus shared fields beyond `__typename`.

> Variant dispatch linchpin: the interface macro can't see a variant's `__typename` (cross-type), so each
> variant `init?` self-guards on its own `__typename` and the interface tries them in turn. Validating this
> end-to-end is the primary wk2 gate item.
